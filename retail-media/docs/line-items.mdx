## What it is

Each campaign consists of one or more line items — a campaign needs at least one line item to run ads. A line item holds the [promoted products](/retail-media/docs/promoted-products) to advertise — each one referencing an entry in your account [catalog](/retail-media/docs/catalogs) — and runs against a single retailer. To advertise across multiple retailers, create a separate line item per retailer.

Currently, the only line item type supported through the API is **Onsite Sponsored Products** — an open auction, cost-per-click (CPC) format where advertisers bid for placement against other advertisers targeting the same inventory.

## Key attributes

* **Start and end dates** — the flight window during which a line item can serve.
* **Budget controls** — optional budget, pacing, and bid settings at the line item level, in addition to controls at the campaign level.
* **Bid settings** — `bidStrategy`, `optimizationStrategy`, and `keywordStrategy` govern how a line item competes in the auction.
* **Promoted products** — the products attached to a line item, up to 500 per line item.

## Keyword targeting

Onsite Sponsored Products line items target search placements using keywords. You can specify which keywords to target positively, which to avoid, and set bids on the most relevant ones.

### Negative keyword targeting

<Info>
  Negative keyword targeting applies **only** to Onsite Sponsored Products campaigns and line items. It lets you specify keywords on which your ads should not appear.
</Info>

Negative keywords can be specified as either **Broad Match** or **Exact Match**.

### Submitted keywords

Submitted (or Positive) keyword targeting enables targeting based on a pool of search phrases that closely match what shoppers type. The API allows you to specify these phrases using the `PositiveExactMatch` match type, comparing the shopper's search term with your specified keywords for an exact match.

[Submitted Keywords](https://help.retailmedia.criteo.com/kb/guide/en/submitted-keywords-pWrW3V33fn/Steps/1632115) will always be **Exact Match**.

**Keyword normalization involves:**

* Removing stop words (e.g., "a," "the," "at").
* [Stemming](https://help.retailmedia.criteo.com/kb/guide/en/keyword-bidding-oBNia2gtXt/Steps/2150023,2150048,2150049) remaining words by trimming prefixes and suffixes ("runner" => "run").
* Sorting remaining words alphabetically.

You can also prune phrases using `NegativeExactMatch` and `NegativeBroadMatch` to remove unwanted matches.

* **Negative exact match**: Removes phrases that match the normalized keyword exactly.
* **Negative broad match**: Removes phrases that match any part of a normalized keyword.

The remaining positive phrases are sent to delivery for bid qualification on search pages; delivery does not use negative keywords.

#### Submitted keyword approval workflow

When you submit a positive keyword, it enters a pending state. Criteo's validation system automatically reviews and approves or rejects the keyword:

* If the keyword is already mapped in the automated keyword model, it is approved.
* If the keyword contains a competitor's brand name, it is rejected and deactivated.
* If the keyword cannot be validated automatically, a Criteo reviewer manually assesses its eligibility.

### Keyword bidding

* Keyword bidding offers more granular control over your ad spend by allowing specific bids on keywords.
* The bid must respect the [minimum bid](/retail-media/docs/minimum-bid) of the line item.

<Info>
  If the line item has a maximum CPC bid set, this will always be enforced, even if a keyword bid exceeds it.
</Info>

**Outcomes based on keyword status:**

* **Approved:** Keyword bids take effect immediately.
* **In Review:** Bids are not effective until the keyword is approved.
* **Rejected:** Bids have no effect.

## Lifecycle

* Campaigns are limited to 10,000 non-archived line items.
* Line items are automatically archived 90 days after their end date.

### Status

| Status | Read-only? | Meaning |
| --- | --- | --- |
| `active` | No — writeable | Delivers ads. The only status you can set directly (along with `paused`). |
| `paused` | No — writeable | Delivery stopped by request. |
| `scheduled` | Yes | Flight dates haven't started yet. |
| `ended` | Yes | Flight dates have passed. |
| `budgetHit` | Yes | The line item's budget is exhausted. |
| `noFunds` | Yes | No funds available from the drawable balance(s). |
| `draft` | Yes | Missing attributes required for the line item to serve. |
| `archived` | Yes | Automatically archived 90 days after the end date. |

All statuses other than `active` and `paused` are applied automatically based on flight dates, financials, or missing required attributes — you can't set them directly. Every status except `active` makes the [campaign](/retail-media/docs/campaigns#status) `inactive`.

Promoted product status (`active` / `paused`, via the pause and unpause endpoints on [Promoted Products](/retail-media/docs/promoted-products)) does not cascade — pausing products on a line item does not change the line item's or campaign's status.

## Relationships

* **Campaign → Line Item** — one-to-many. A campaign needs at least one line item to run.
* **Line Item → Promoted Products** — one-to-many. [Promoted Products](/retail-media/docs/promoted-products) are the actual products attached to a line item.
* **Promoted Products → Catalog** — each promoted product references an entry in the advertiser's [catalog](/retail-media/docs/catalogs); what's synced there determines what's available to promote. The catalog reference lives on the product, not the line item.
* **Line Item → Retailer** — a line item runs against a single retailer, chosen via [Retailer Search](/retail-media/docs/retailer-search) and narrowed with [Category Search](/retail-media/docs/category-search).

See the [Campaign Management Overview](/retail-media/docs/campaign-management-overview) for how Line Items fit with the rest of the campaign hierarchy.

***

## Constraints and gotchas

* A line item can only target one retailer; advertising across retailers requires one line item per retailer.
* Up to 500 promoted products per line item.
* Line items can and should feature multiple products — you don't need a separate line item per product.

<Warning>
  **Don't duplicate products across line items in the same campaign.** Line items with overlapping products under the same campaign scale much slower and can prevent you from meeting your spending goals.
</Warning>

* Preferred Deals are currently in beta and available only to Retailer partners. Contact your Criteo Account Manager for access. Where Onsite Sponsored Products line items have bid settings and optional budget/pacing controls, Preferred Deals line items require budget and pacing controls, with optional capping controls.

## Budget Overrides

<Card title="Budget Override Endpoints" icon="arrow-up-right-from-square" href="/retail-media/docs/onsite-sponsored-products-line-items" horizontal />

You can set a monthly or daily budget override at the line item level to temporarily spend more or less than the line item's current budget for the months or dates you specify. The override takes effect at midnight in your time zone on the first day of the month or date range you select. Budget overrides are also available at the [campaign level](/retail-media/docs/campaigns#budget-overrides).

| Method | Endpoint | Description |
| --- | --- | --- |
| `GET` | `/line-items/{lineItemId}/line-item-budget-overrides` | Retrieves all existing budget overrides for a line item. |
| `PUT` | `/line-items/{lineItemId}/line-item-budget-override` | Replaces all existing line item budget override settings. Use this endpoint to add, remove, or update overrides. |

**Attributes**

| Attribute | Type | Description |
| --- | --- | --- |
| `monthlyLineItemBudgetOverrides` | `list<object>` | Monthly overrides, in chronological order. Each entry has `startMonth`, `duration`, `maxMonthlySpend`, `status`. |
| `dailyLineItemBudgetOverrides` | `list<object>` | Daily overrides, in chronological order. Each entry has `startDate`, `duration`, `maxDailySpend`, `status`. |
| `startMonth` | `string` | Start month (`YYYY-MM`). If `null`, defaults to the month following the last item in the override sequence. Writeable, nullable. |
| `startDate` | `date` | Start date (`YYYY-MM-DD`). If `null`, defaults to the date following the last item in the override sequence. Writeable, nullable. |
| `duration` | `string` | Length of the override: months for monthly overrides (`1M`, `2M`, ...) or days for daily overrides (`1D`, `2D`, ...). Writeable, not nullable. |
| `maxMonthlySpend` / `maxDailySpend` | `decimal` | Spend cap for the override (`>= 0.0`). Writeable, not nullable. |
| `status` | `enum` | Computed status: `Expired`, `Active`, `Upcoming`. Read-only. |

<Warning>
  Budget overrides cannot overlap. Scheduling a new override that overlaps the duration of an existing one returns a `400` validation error.

  <Frame>
  ![fdb6c02 image](/images/retail-media/docs/fdb6c02-image.png)
  </Frame>
</Warning>

**Sample Request — Update Line Item Budget Override**

```bash
curl -L -X PUT 'https://api.criteo.com/{version}/retail-media/line-items/446397611671216128/line-item-budget-overrides' \
-H 'Content-Type: application/json' \
-H 'Accept: application/json' \
-H 'Authorization: Bearer <MY_ACCESS_TOKEN>' \
-d '{
  "data": {
    "type": "<string>",
    "attributes": {
      "dailyLineItemBudgetOverrides": [
        { "duration": "5D", "startDate": "2023-12-01", "maxDailySpend": "5", "status": "Upcoming" }
      ],
      "monthlyLineItemBudgetOverrides": [
        { "duration": "3M", "maxMonthlySpend": "12", "startMonth": "2023-12", "status": "Upcoming" }
      ]
    }
  }
}'
```

## Get all Line Items

This endpoint lists all line items in the specified campaign.

Results are paginated using `pageIndex` and `pageSize` query parameters; if omitted, defaults to `0` and `25`, respectively. See [API Response](/criteo-apis/docs/api-response#pagination).

<EndpointBadge method="get">
```http
https://api.criteo.com/{version}/retail-media/accounts/{accountId}/line-items
```
</EndpointBadge>
