A balance holds the funds an account can spend on campaigns. It caps spend across every campaign linked to it: when their combined cost reaches the balance amount, all linked campaigns stop, even before their end dates. A campaign needs at least one balance to run.

## Balance types

| Type | Funded by | Scope | `retailerId` |
| --- | --- | --- | --- |
| **Criteo balance** | The advertiser | Not scoped to a retailer; linked campaigns can serve on any retailer available to the account | `null` |
| **Retailer-budgets balance** | The retailer | Scoped to the retailer in `retailerId`; linked campaigns must be retailer-native | Set |

Retailer-budgets balances support the Commerce Max Retailer Budgets buying model, where the retailer funds campaign budgets instead of the advertiser. They're returned on API version `2026-01` and later and hidden by default on earlier versions.

### Retailer-budgets balance rules

The `retailerId` must be consistent across balance → campaign → line item:

- Campaigns drawing on a retailer-budgets balance must be created with the balance's `retailerId`. A mismatch returns `RetailerMismatchWithBalance`.
- Line items in those campaigns must set `targetRetailerId` to the campaign's `retailerId`. A mismatch returns `RetailerMismatchWithCampaign`.
- Campaigns can't be removed from a retailer-budgets balance. Trying returns `RetailerBilledBalanceImmutable`.
- Retailer-budgets balances can't be created through the API; retrieve them with `GET /accounts/{accountId}/balances`.

To check which budget models a retailer supports before creating a campaign, read `budgetModel` (`capped`, `uncapped`, `retailerBudgets`, or `criteoBudgets`) from [Retailer Search](/retail-media/docs/retailer-search).

## What each account type can do

Buyers (demand accounts) can read balances and link campaigns to them. Retailers (supply and Private Market accounts) can also create and fund balances.

| Action | Endpoint | Buyers | Retailers |
| --- | --- | --- | --- |
| View balances and their history | `GET /accounts/{accountId}/balances`, `GET /balances/{balanceId}/history` | Yes | Yes |
| Create a balance | `POST /accounts/{accountId}/balances` | No | Yes |
| Edit name, dates, or memo | `PATCH /accounts/{accountId}/balances/{balanceId}` | No | Yes |
| Add or remove funds | `POST /accounts/{accountId}/balances/{balanceId}/add-funds` | No | Yes |
| Link campaigns | `POST /balances/{balanceId}/campaigns/append` | Yes | Yes |
| Unlink campaigns | `POST /balances/{balanceId}/campaigns/delete` | Yes, except from retailer-budgets balances | Yes, except from retailer-budgets balances |

Retailers can edit only balances with `privateMarketBillingType` set to `billByRetailer`, which covers every balance created through the API. Balances set to `billByCriteo` were created in Commerce Max and can only be edited there.

## Balance statuses

| Status | Meaning |
| --- | --- |
| `active` | Has funds and today is between its start and end dates. Linked campaigns can spend. |
| `scheduled` | Has funds, but its start date is in the future. Linked campaigns can't spend yet. |
| `ended` | Out of funds or past its end date. Linked campaigns can't spend. |
